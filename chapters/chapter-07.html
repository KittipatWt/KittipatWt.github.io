บทที่ 7: Priority Queues (Binary Heaps)

204252 Data Structures and Analysis · อ้างอิงสไลด์ของ Thapanapong Rukkanchanunt และ Jakarin Chawachat

1. Priority Queue ADT

Priority Queue เป็น Abstract Data Type (ADT) ที่เก็บกลุ่มของข้อมูล โดยแต่ละตัวมี priority (key) และรองรับ 2 การทำงานหลัก:

  • insert(x) — ใส่ข้อมูล x เข้าไปในคิว
  • deleteMin() — ลบและคืนค่าตัวที่มี key น้อยที่สุด (priority สูงสุดใน Min-Priority Queue)

เปรียบเทียบกับ Container อื่น

  • Stack: เข้าหลัง ออกก่อน (LIFO) → เข้าถึงตัวที่ ใหม่ ที่สุด
  • Queue: เข้าก่อน ออกก่อน (FIFO) → เข้าถึงตัวที่ เก่า ที่สุด
  • Priority Queue: ตัวที่ priority สูงสุดออกก่อน → เข้าถึงตัวที่ น้อยที่สุด/มากที่สุด

ตัวอย่างการใช้งานจริง

  • OS Scheduler — เลือก process ที่ priority สูงสุด / เหลือเวลาทำงานสั้นที่สุด
  • Network Router — ส่งแพ็กเก็ตเสียง/วิดีโอก่อนทราฟฟิกทั่วไป
  • Graph Algorithms — Prim's MST, Dijkstra's Shortest Path, Huffman Coding

2. ทำไมต้อง Heap? วิเคราะห์ต้นทุนของวิธีง่ายๆ

ถ้าสร้าง Priority Queue จาก list ธรรมดา จะได้ความเร็วดังนี้ (N = จำนวนข้อมูล):

โครงสร้างข้อมูลinsert(x)deleteMin()
Unsorted Array / ListO(1)O(N) (สแกนหาค่าน้อยสุด)
Sorted Array / ListO(N) (ต้องเลื่อนข้อมูล)O(1) (เอาตัวแรก)

สรุป BST ทำเกินความจำเป็น เพราะเรียงข้อมูลทั้งหมดและต้องใช้ pointer ที่แพง ส่วน Binary Heap เป็น complete binary tree แบบพิเศษที่ ไม่ใช้ pointer (เก็บใน array) และทำทั้งสองการทำงานได้ใน O(log N) กรณีเลวร้ายที่สุด

3. คุณสมบัติของ Binary Heap

3.1 Structure Property: Complete Binary Tree

Heap คือ Complete Binary Tree — ทุก level เต็มหมด ยกเว้น level ล่างสุดที่อาจไม่เต็ม แต่ต้องเติมจาก ซ้ายไปขวา ไม่มีช่องว่างคั่น จึงเก็บใน array ที่เริ่มต้นที่ index 1 ได้ตรงๆ:

i01234567
val–13211624311968
สูตรสำคัญ (ท่องไว้สอบ!)
  • Left child ของ i = 2i
  • Right child ของ i = 2i + 1
  • Parent ของ i = ⌊i / 2⌋
  • Index 0 = sentinel / dummy (ไม่เก็บข้อมูลจริง)

ตัวอย่าง: node ที่ index 5 (ค่า 31) → parent = ⌊5/2⌋ = 2 (ค่า 21), left child = 10, right child = 11

3.2 Heap-Order Property

กฎของ Min-Heap: สำหรับทุก node X ที่ไม่ใช่ root ค่า key ของ parent ต้อง น้อยกว่าหรือเท่ากับ (≤) key ของ X ผลคือ ค่าต่ำสุดอยู่ที่ root เสมอ → findMin() เป็น O(1)

ข้อควรระวัง Heap ไม่ได้เรียงข้อมูลทั้งหมด! ลูกซ้ายกับลูกขวา ไม่จำเป็น ต้องเรียงกัน (เช่น 21 กับ 16 ด้านบน) รู้แค่ parent ≤ child เท่านั้น

4. Insert: Percolate Up

แนวคิดคือ "ถือ hole ไว้แล้วดันขึ้นข้างบน":

  1. สร้าง hole ที่ตำแหน่งว่างถัดไปของ complete tree (index size+1)
  2. ถ้า x ใส่ใน hole ได้โดยไม่ผิดกฎ heap-order → วางลงไปเลย
  3. ไม่เช่นนั้น เลื่อน parent ลงมา ใน hole (hole เลื่อนขึ้น) แล้วทำซ้ำ

ตัวอย่าง: insert 14

Step 1: สร้าง hole

สร้าง hole ที่ index 11 · เทียบ 14 กับ parent 31 (index 5): 14 < 31 → ต้อง bubble up

Step 2: Percolate Up

เลื่อน 31 ลงใน hole · hole ย้ายไป index 5 · เทียบ 14 กับ parent 21 (index 2): 14 < 21 → bubble up อีก

Step 3: Percolate Up

เลื่อน 21 ลง · hole ย้ายไป index 2 · เทียบ 14 กับ parent 13 (index 1): 14 > 13 → hole หยุดที่นี่

Step 4: วางค่า

วาง 14 ลงใน hole ที่ index 2 · heap-order ถูกต้องครบ ✔

โค้ด C++ (ตาม Weiss)

โค้ดนี้คัดลอกค่าที่จะ insert ไปไว้ที่ array[0] เพื่อใช้เป็น sentinel ทำให้ลูปหยุดเองที่ root โดยไม่ต้องเช็ก hole > 1 (เพราะ x < array[0] เป็นเท็จเสมอ)

C++ · BinaryHeap::insert
// Insert item x, allowing duplicates.
void insert( const Comparable & x )
{
    if( currentSize == array.size( ) - 1 )   // array เต็ม → ขยายเป็น 2 เท่า
        array.resize( array.size( ) * 2 );

    // Percolate up
    int hole = ++currentSize;                // 1) สร้าง hole ที่ตำแหน่งว่างถัดไป
    Comparable copy = x;
    array[ 0 ] = std::move( copy );          // sentinel: ตัวหยุดลูปที่ root

    for( ; x < array[ hole / 2 ]; hole /= 2 )
        array[ hole ] = std::move( array[ hole / 2 ] );  // 3) เลื่อน parent ลง
    array[ hole ] = std::move( array[ 0 ] ); // 2) วางค่าลงใน hole
}
Complexity O(log N) ในกรณีเลวร้ายที่สุด (ไต่ขึ้นสุด root = ความสูงของต้นไม้) แต่โดยเฉลี่ยใช้เพียงประมาณ 2.6 comparisons ดังนั้น insert โดยเฉลี่ยคือ O(1)

5. deleteMin: Percolate Down

ค่าต่ำสุดอยู่ที่ root อยู่แล้ว ปัญหาคือหลังลบจะเกิด hole ที่ root ต้องซ่อมให้ heap ยังเป็น complete tree:

  1. ลบ root (ค่าต่ำสุด) → เกิด hole ที่ index 1
  2. หยิบ ตัวสุดท้าย ของ heap มาเก็บไว้ที่ tmp (size ลดลง 1)
  3. เลื่อน child ที่เล็กกว่า ของ hole ขึ้นมา (hole ลงไปข้างล่าง)
  4. ทำซ้ำจนกว่า tmp วางใน hole ได้โดยไม่ผิดกฎ heap-order
Edge Case: Single Child ถ้า heap มีจำนวนตัวเป็น เลขคู่ จะมี node หนึ่งที่มีลูกซ้ายตัวเดียว (ไม่มีลูกขวา) ต้องเช็กก่อนเทียบ array[child + 1] ไม่เช่นนั้นจะอ่านเกินขอบเขตของ heap

ตัวอย่าง: deleteMin (ต่อจาก heap หลัง insert 14)

Step 1: ลบ root & ถือ 31

ลบ root 13 → hole ที่ index 1 · หยิบตัวสุดท้าย 31 (index 11) มาถือไว้ · size เหลือ 10

Step 2: Percolate Down

เทียบ children 14 กับ 16 → ตัวเล็กคือ 14 · 31 > 14 → เลื่อน 14 ขึ้น · hole ลงไป index 2

Step 3: Percolate Down

เทียบ children 24 กับ 21 → ตัวเล็กคือ 21 · 31 > 21 → เลื่อน 21 ขึ้น · hole ลงไป index 5

Step 4: วางค่า

เทียบ child 32 (index 10, มีตัวเดียว) · 31 < 32 → หยุด · วาง 31 ที่ index 5 ✔

โค้ด C++

C++ · BinaryHeap::deleteMin / percolateDown
void deleteMin( )
{
    if( isEmpty( ) )
        throw UnderflowException{ };

    array[ 1 ] = std::move( array[ currentSize-- ] );  // เอาตัวสุดท้ายมาไว้ที่ root แล้ว size ลด 1
    percolateDown( 1 );
}

void percolateDown( int hole )
{
    int child;
    Comparable tmp = std::move( array[ hole ] );       // tmp = ค่าที่ต้องหาที่วาง

    for( ; hole * 2 <= currentSize; hole = child )     // ทำต่อตราบที่ hole ยังมี child ซ้าย
    {
        child = hole * 2;                              // เริ่มที่ left child

        // ถ้ามี right child และมันเล็กกว่า left → เลือก right
        if( child != currentSize && array[ child + 1 ] < array[ child ] )
            ++child;

        if( array[ child ] < tmp )
            array[ hole ] = std::move( array[ child ] ); // เลื่อน child ที่เล็กกว่าขึ้น
        else
            break;                                       // tmp วางได้แล้ว
    }
    array[ hole ] = std::move( tmp );
}
Complexity deleteMin() เป็น O(log N) ทั้งกรณีเฉลี่ยและเลวร้ายที่สุด เพราะตัวสุดท้ายที่ถูกยกขึ้นมามักมีค่าสูง จึงมักจมลงเกือบถึงล่างสุด

7. การประยุกต์ใช้

7.1 Selection Problem

โจทย์: จาก N ตัว ให้หาตัวที่ k ที่เล็กที่สุด (หรือใหญ่ที่สุด)

Algorithmวิธีเวลา
7A: k-th smallestอ่านข้อมูลลง array → buildHeap() (O(N)) → เรียก deleteMin() k ครั้ง (O(k log N))O(N + k log N)
7B: k-th largestเก็บ Min-Heap ขนาด k ที่มี k ตัวใหญ่สุดที่เจอแล้ว · ตัวใหม่ที่ใหญ่กว่า root → แทนที่ root แล้ว percolate downO(N log k)

Algorithm 7A: หาตัวที่ 3 ที่เล็กที่สุดของ [150, 80, 40, 30, 10, 70, 110]

  1. buildHeap จัด array ให้เป็น min-heap ในที่เดิม → [10, 30, 40, 150, 80, 70, 110]
  2. deleteMin() ครั้งที่ 1 → ได้ 10 · heap = [30, 80, 40, 150, 110, 70]
  3. deleteMin() ครั้งที่ 2 → ได้ 30 · heap = [40, 80, 70, 150, 110]
  4. deleteMin() ครั้งที่ 3 → ได้ 40 ✔ จบ

ผลลัพธ์: ตัวที่ 3 ที่เล็กที่สุดคือ 40

Algorithm 7B: หาตัวที่ 3 ที่ใหญ่ที่สุดของ [15, 20, 5, 30, 10, 25, 8]

เก็บ Min-Heap ขนาด k = 3 แทน 3 ตัวที่ใหญ่ที่สุด:

  1. 3 ตัวแรก [15, 20, 5] → build heap ได้ [5, 20, 15] (root = 5)
  2. ตัว 30: 30 > root 5 → แทนที่ root แล้ว percolate down → [15, 20, 30] (root = 15)
  3. ตัว 10: 10 ≤ root 15 → ข้าม
  4. ตัว 25: 25 > root 15 → แทนที่ root → [20, 25, 30] (root = 20)
  5. ตัว 8: 8 ≤ root 20 → ข้าม

ผลลัพธ์: root ของ heap สุดท้ายคือ 20 = ตัวที่ 3 ที่ใหญ่ที่สุด

เลือกใช้อันไหน? 7B ใช้หน่วยความจำแค่ O(k) และเหมาะกับข้อมูลที่ไหลเข้ามาเรื่อยๆ (stream) ส่วน 7A เร็วกว่าเมื่อ k น้อยมากเมื่อเทียบกับ N

7.2 Discrete Event Simulation

ในการจำลองเหตุการณ์ (เช่น ลูกค้าเข้าธนาคาร) ต้องประมวลผลเหตุการณ์ ตามลำดับเวลา:

Tick-by-Tick (ไม่มีประสิทธิภาพ)

• เดินนาฬิกาทีละ 1 tick
• เช็กทุก tick ว่ามีเหตุการณ์เกิดไหม
• ข้อเสีย: เวลาทำงานขึ้นกับ ขนาดของมาตราเวลา ไม่ใช่จำนวนเหตุการณ์

Event-Driven (ใช้ Priority Queue)

• เก็บเหตุการณ์ในอนาคตใน PQ เรียงตามเวลา
• deleteMin() เอาเหตุการณ์ถัดไป แล้ว กระโดดนาฬิกาไปที่เวลานั้นเลย
• ข้อดี: เวลาทำงานเป็นสัดส่วนกับ จำนวนเหตุการณ์ เท่านั้น

C++ · แนวคิด event loop
PriorityQueue<Event> pq;           // เรียงตาม event.time
pq.insert( Event{ 0, ARRIVAL } );   // เหตุการณ์เริ่มต้น

while( !pq.isEmpty( ) )
{
    Event e = pq.findMin( );
    pq.deleteMin( );
    clock = e.time;                 // กระโดดนาฬิกาไปที่เวลาของเหตุการณ์ทันที
    process( e );                   // อาจ insert เหตุการณ์ใหม่ (เช่น DEPARTURE) กลับเข้า pq
}
