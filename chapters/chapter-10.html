1. ปัญหาการเรียงลำดับ & Stability

1.1 นิยาม

  • Input: ลำดับของ record N ตัว ⟨a₁, a₂, …, aN⟩
  • Output: permutation ⟨a′₁, …, a′N⟩ ของอินพุต ที่ a′₁ ≤ a′₂ ≤ … ≤ a′N
  • ข้อมูลเก็บใน array หรือ list · key เปรียบเทียบได้ (มี strict weak ordering คือนิยาม <)
  • เน้น Internal Sorting — เรียงในหน่วยความจำหลัก (โดยทั่วไป N < 10⁷)

1.2 Comparison Model

วิธีเดียวที่ใช้ได้เพื่อรู้ลำดับของ element คือ เปรียบเทียบทีละคู่ (aᵢ < aⱼ, aᵢ ≤ aⱼ …) — ห้ามดูค่าไบนารีภายในของ key (ไม่มี bitwise หรือ hashing) ภายใต้โมเดลนี้ algorithm ใดๆ มี lower bound กรณีเลวร้ายที่สุดเป็น Ω(N log N) การเปรียบเทียบ (พิสูจน์ในหัวข้อ 7)

1.3 Stability

Sorting algorithm เป็น stable ถ้ารักษาลำดับสัมพัทธ์เดิมของ record ที่มี key เท่ากัน: ถ้า key(aᵢ) = key(aⱼ) และ aᵢ อยู่ก่อน aⱼ ในอินพุต aᵢ ต้องอยู่ก่อน aⱼ ในผลลัพธ์

ทำไมสำคัญ: ใช้เรียงหลาย key (multi-key sort) เช่น เรียงรายชื่อนักศึกษาตามชื่อก่อน แล้วค่อยเรียงตามนามสกุล — ถ้า stable คนที่นามสกุลเดียวกันจะยังเรียงตามชื่ออยู่

2. Selection Sort

แบ่ง array เป็น sorted prefix กับ unsorted suffix แต่ละ pass สแกน suffix หาค่าน้อยสุด แล้ว swap เข้ากับตัวแรกของ suffix ทำให้ prefix ยาวขึ้น 1

  • ใช้ swap เพียง O(N) ครั้ง
  • เวลาไม่ขึ้นกับลำดับของอินพุต — Θ(N²) เสมอ
  • Unstable
C++ · selectionSort
template <typename Comparable>
void selectionSort(vector<Comparable> & a) {
    for (size_t i = 0; i < a.size() - 1; ++i) {
        size_t min_idx = i;
        // หาค่าน้อยสุดใน unsorted suffix
        for (size_t j = i + 1; j < a.size(); ++j) {
            if (a[j] < a[min_idx]) {
                min_idx = j;
            }
        }
        // swap กับตัวแรกของ unsorted suffix
        if (min_idx != i) {
            std::swap(a[i], a[min_idx]);
        }
    }
}

ตัวอย่าง: [5a, 3, 8, 2, 5b]

  1. Pass 0: min = 2 → swap กับ 5a → [2, 3, 8, 5a, 5b]
  2. Pass 1: min = 3 อยู่ที่ index 1 แล้ว → ไม่ swap
  3. Pass 2: min ของ [8, 5a, 5b] = 5a → swap กับ 8 → [2, 3, 5a, 8, 5b]
  4. Pass 3: min ของ [8, 5b] = 5b → swap → [2, 3, 5a, 5b, 8]

ทำไมถึง unstable? ตัวอย่างค้าน: [2a, 2b, 1]

Pass 0 หา min = 1 → swap กับ 2a (ตัวแรก) → [1, 2b, 2a] → 2a กับ 2b สลับลำดับกัน! (ลองใน Simulation: ใส่ 2, 2, 1)

Complexity

  • Comparisons: (N−1) + (N−2) + … + 1 = N(N−1)/2 เสมอ → Θ(N²) ทั้ง best / worst / average
  • Swaps: ไม่เกิน N−1 ครั้ง → Θ(N) · ได้เปรียบเมื่อการ swap record แพงมาก เพราะเขียนกลับหน่วยความจำน้อยที่สุดในกลุ่ม quadratic sort

3. Insertion Sort

มี N−1 pass (p = 1 ถึง N−1) · ก่อน pass p ถือว่า index 0..p−1 เรียงแล้ว · หยิบ tmp = a[p] เลื่อนไปทางซ้ายจนเจอตำแหน่งที่ถูกต้อง โดยเลื่อนตัวที่ใหญ่กว่าไปทางขวาเพื่อเปิด hole ให้ tmp

  • ง่ายและมีประสิทธิภาพกับ array ขนาดเล็ก
  • Adaptive: ข้อมูลเรียงอยู่แล้วใช้เวลา O(N)
  • Stable
C++ · insertionSort (Weiss Figure 7.2)
template <typename Comparable>
void insertionSort( vector<Comparable> & a ) {
    for( int p = 1; p < a.size( ); ++p ) {
        Comparable tmp = std::move( a[p] );
        int j;
        for( j = p; j > 0 && tmp < a[j - 1]; --j ) {
            a[j] = std::move( a[j - 1] );
        }
        a[j] = std::move( tmp );
    }
}

ตัวอย่าง: [34, 8, 64, 51, 32, 21]

Passการทำงานผล (prefix ที่เรียงแล้ว)
1แทรก 8 → shift 34[8, 34 | 64, 51, 32, 21]
2แทรก 64 → ไม่ shift (64 > 34)[8, 34, 64 | 51, 32, 21]
3แทรก 51 → shift 64[8, 34, 51, 64 | 32, 21]
4แทรก 32 → shift 64, 51, 34[8, 32, 34, 51, 64 | 21]
5แทรก 21 → shift 64, 51, 34, 32[8, 21, 32, 34, 51, 64]

Complexity

  • Worst: อินพุตเรียงย้อน → inner loop ทำ p ครั้งในแต่ละ p → Σp = N(N−1)/2 = O(N²)
  • Best: อินพุตเรียงแล้ว → เงื่อนไข tmp < a[j-1] เป็นเท็จทันที → O(N) เทียบ ไม่มี shift
  • Average: Θ(N²)

3.1 Inversion

Inversion คือคู่ (i, j) ที่ i < j แต่ a[i] > a[j] · การ shift แต่ละครั้งของ insertion sort ลบ inversion ได้พอดี 1 คู่ จึงใช้เวลา O(I + N) เมื่อ I คือจำนวน inversion

Theorem: จำนวน inversion เฉลี่ย ของ array ที่ไม่เรียง N ตัวที่ต่างกัน คือ Iavg = N(N−1)/4
พิสูจน์ ให้ L เป็นลิสต์ใดๆ และ Lr คือลิสต์กลับด้าน (เช่น L = [3, 4, 1, 5, 2], Lr = [2, 5, 1, 4, 3]) · คู่ (x, y) ใดๆ เป็น inversion ใน L หรือ Lr อย่างใดอย่างหนึ่งเท่านั้น · จำนวนคู่ทั้งหมดคือ N(N−1)/2 ดังนั้นผลรวม inversion ของ L กับ Lr = N(N−1)/2 · โดยสมมาตร ลิสต์สุ่มมี inversion เฉลี่ยครึ่งหนึ่ง = N(N−1)/4 = Θ(N²) ∎
Corollary algorithm ใดๆ ที่ swap ได้แต่ element ที่อยู่ติดกัน ต้องใช้เวลาเฉลี่ย Ω(N²) (เพราะแต่ละ swap ลด inversion ได้อย่างมาก 1)

4. Merge Sort

Divide-and-Conquer: แบ่ง array เป็น 2 ส่วนเท่าๆ กัน → เรียง แต่ละส่วนแบบ recursive → merge สองส่วนที่เรียงแล้วเป็น array เดียว

  • Merge: รวม subarray ที่เรียงแล้ว 2 ชุดใน O(N) ต้องใช้ array ชั่วคราวขนาด N
  • เทียบสมาชิกหัวของทั้งสองฝั่ง คัดลอกตัวที่เล็กกว่าแล้วขยับ pointer
C++ · mergeSort driver + recursion
// Public driver
template <typename Comparable>
void mergeSort( vector<Comparable> & a ) {
    vector<Comparable> tmpArray( a.size( ) );
    mergeSort( a, tmpArray, 0, a.size( ) - 1 );
}

// Internal recursive method
template <typename Comparable>
void mergeSort( vector<Comparable> & a, vector<Comparable> & tmpArray,
                int left, int right ) {
    if( left < right ) {
        int center = ( left + right ) / 2;
        mergeSort( a, tmpArray, left, center );
        mergeSort( a, tmpArray, center + 1, right );
        merge( a, tmpArray, left, center + 1, right );
    }
}
C++ · merge
template <typename Comparable>
void merge( vector<Comparable> & a, vector<Comparable> & tmpArray,
            int leftPos, int rightPos, int rightEnd ) {
    int leftEnd = rightPos - 1;
    int tmpPos = leftPos;
    int numElements = rightEnd - leftPos + 1;
    while( leftPos <= leftEnd && rightPos <= rightEnd )
        if( a[ leftPos ] <= a[ rightPos ] )
            tmpArray[ tmpPos++ ] = std::move( a[ leftPos++ ] );
        else
            tmpArray[ tmpPos++ ] = std::move( a[ rightPos++ ] );
    while( leftPos <= leftEnd )        // คัดลอกส่วนที่เหลือของครึ่งแรก
        tmpArray[ tmpPos++ ] = std::move( a[ leftPos++ ] );
    while( rightPos <= rightEnd )      // คัดลอกส่วนที่เหลือของครึ่งหลัง
        tmpArray[ tmpPos++ ] = std::move( a[ rightPos++ ] );
    for( int i = 0; i < numElements; ++i, --rightEnd )   // คัดลอกกลับ
        a[ rightEnd ] = std::move( tmpArray[ rightEnd ] );
}

4.2 วิเคราะห์ด้วย Recurrence

สมมติ N เป็นยกกำลัง 2: T(1) = 1 และ T(N) = 2T(N/2) + N (2T(N/2) = เรียงสองครึ่ง, N = merge แบบ linear)

วิธีที่ 1: Telescoping

หารทั้งสองข้างด้วย N: T(N)/N = T(N/2)/(N/2) + 1 · เขียนซ้ำสำหรับ N/2, N/4, …, 2: T(N/2)/(N/2) = T(N/4)/(N/4) + 1, …, T(2)/2 = T(1)/1 + 1 · บวกทุกสมการ พจน์ตรงกลางตัดกัน:

T(N)/N = T(1)/1 + log N  ⟹  T(N) = N log N + N = O(N log N)

วิธีที่ 2: Substitution

T(N) = 2[2T(N/4) + N/2] + N = 4T(N/4) + 2N = 8T(N/8) + 3N = … = 2kT(N/2k) + kN · ให้ 2k = N (k = log N): T(N) = N·T(1) + N log N = N log N + N = O(N log N)

สรุป Merge Sort
  • เวลา: Θ(N log N) ทั้ง best / average / worst — สม่ำเสมอ ไม่ขึ้นกับลำดับอินพุต
  • Space: O(N) เพิ่ม (tmpArray) — ข้อเสียเมื่อหน่วยความจำจำกัด
  • Stable: เมื่อเท่ากันเลือกจากครึ่งซ้ายก่อน (a[leftPos] <= a[rightPos])

5. Quicksort

Divide-and-Conquer เหมือน Merge Sort แต่เรียงแบบ in-place:

  1. Divide: เลือก pivot v แล้ว partition ที่เหลือเป็น S₁ = {x ≤ v} และ S₂ = {x ≥ v}
  2. Conquer: เรียง S₁ และ S₂ แบบ recursive
  3. Combine: ไม่ต้องทำอะไร — partition ทำในที่เดิม ผลคือ S₁ เรียงแล้ว, v, S₂ เรียงแล้ว ต่อกันพอดี

5.1 การเลือก Pivot

  • ตัวแรก (วิธีที่ผิด): ถ้าอินพุตเรียงอยู่แล้วหรือกลับด้าน pivot จะเป็นค่าต่ำสุด/สูงสุดเสมอ → ฝั่งหนึ่งว่าง อีกฝั่งมี N−1 ตัว → T(N) = T(N−1) + O(N) = Θ(N²)
  • สุ่ม: ปลอดภัยกับอินพุตที่เรียงแล้ว แต่การสุ่มตัวเลขมีต้นทุนสูง
  • Median-of-Three: ประมาณ median ด้วย median ของ a[left], a[center], a[right] · กำจัด worst case ของอินพุตที่เรียงแล้ว และลดการเปรียบเทียบได้ ≈ 14%
C++ · median3
template <typename Comparable>
const Comparable & median3( vector<Comparable> & a, int left, int right ) {
    int center = ( left + right ) / 2;
    if( a[ center ] < a[ left ] )
        std::swap( a[ left ], a[ center ] );
    if( a[ right ] < a[ left ] )
        std::swap( a[ left ], a[ right ] );
    if( a[ right ] < a[ center ] )
        std::swap( a[ center ], a[ right ] );

    // ซ่อน pivot ไว้ที่ตำแหน่ง right - 1
    std::swap( a[ center ], a[ right - 1 ] );
    return a[ right - 1 ];
}

ผลข้างเคียงของ median3: a[left], a[center], a[right] ถูกเรียงในที่เดิม · pivot อยู่ที่ a[right − 1] · a[left] ทำหน้าที่เป็น sentinel ของ j · a[right] ≥ pivot อยู่แล้ว

5.2 In-Place Partitioning

เป้าหมาย: กลุ่ม ≤ pivot ไปทางซ้าย, ≥ pivot ไปทางขวา

  1. ตั้ง i = left, j = right − 1
  2. วนซ้ำ: เพิ่ม i ตราบที่ a[i] < pivot · ลด j ตราบที่ a[j] > pivot · ถ้า i < j ให้ swap a[i], a[j] แล้วทำต่อ · ไม่เช่นนั้น break
  3. คืน pivot: swap a[i] กับ a[right − 1]
รายละเอียดสำคัญ: key ที่เท่ากับ pivot ถ้า a[i] == pivot และ a[j] == pivot ให้ หยุดทั้งสอง pointer แล้ว swap — แม้จะ swap เกินความจำเป็น แต่ป้องกัน pointer วิ่งเลยและรับประกันว่า partition สมดุลเมื่อ array เต็มไปด้วย key ซ้ำ

5.3 Cutoff สำหรับ Subarray เล็ก

สำหรับ array เล็กมาก (N ≤ 10) quicksort ช้ากว่า sort แบบง่ายอย่าง insertion sort เพราะ overhead ของการเรียกฟังก์ชัน → ไม่ recursive quicksort ช่วงที่ขนาด ≤ 10 แต่เรียก insertion sort แทน (เงื่อนไข: right − left + 1 < 10 ⟹ left + 9 ≥ right)

C++ · quicksort
template <typename Comparable>
void quicksort( vector<Comparable> & a, int left, int right ) {
    if( left + 10 <= right ) {            // ขนาด ≥ 10: ใช้ quicksort
        const Comparable & pivot = median3( a, left, right );
        int i = left, j = right - 1;
        for( ; ; ) {
            while( a[ ++i ] < pivot ) { }
            while( pivot < a[ --j ] ) { }
            if( i < j )
                std::swap( a[ i ], a[ j ] );
            else
                break;
        }
        std::swap( a[ i ], a[ right - 1 ] );   // คืน pivot
        quicksort( a, left, i - 1 );           // เรียง S1
        quicksort( a, i + 1, right );          // เรียง S2
    }
    else                                       // ขนาดเล็ก: ใช้ insertion sort
        insertionSort( a, left, right );
}

5.5 วิเคราะห์ Complexity

Worst Case

pivot เป็นค่าต่ำสุด/สูงสุดเสมอ: T(N) = T(N−1) + cN · telescoping: T(N) − T(N−1) = cN, T(N−1) − T(N−2) = c(N−1), …, T(2) − T(1) = 2c · รวมทั้งหมด T(N) = T(1) + c·Σi=2..N i = Θ(N²)

Best Case

pivot เป็น median พอดีทุกครั้ง: T(N) = 2T(N/2) + cN ⟹ Θ(N log N) (เหมือน Merge Sort)

Average Case

สมมติขนาดของ partition i (0 ถึง N−1) เกิดได้เท่าๆ กัน ความน่าจะเป็น 1/N: T(N) = (2/N)·Σj=0..N−1 T(j) + cN

  1. คูณ N: N·T(N) = 2·Σj=0..N−1 T(j) + cN² … (1)
  2. เขียนสำหรับ N−1: (N−1)·T(N−1) = 2·Σj=0..N−2 T(j) + c(N−1)² … (2)
  3. (1) − (2) กำจัด summation: N·T(N) − (N−1)·T(N−1) = 2T(N−1) + c(2N−1)
  4. จัดรูปและทิ้ง −c: N·T(N) = (N+1)·T(N−1) + 2cN
  5. หารด้วย N(N+1): T(N)/(N+1) = T(N−1)/N + 2c/(N+1)
  6. Telescope: T(N)/(N+1) = T(1)/2 + 2c·Σi=3..N+1 1/i
  7. ใช้ harmonic number Σ 1/i ≈ ln M: T(N)/(N+1) ≈ 2c ln N ⟹ T(N) ≈ 2cN ln N = O(N log N)

Stability: Unstable — การย้าย element ข้าม pivot ระหว่าง partition ทำให้ลำดับของตัวที่เท่ากันเปลี่ยนได้

6. Heapsort

ใช้ Binary Heap เรียงแบบ in-place ไม่ใช้หน่วยความจำเพิ่ม เพื่อเรียงจากน้อยไปมาก:

  1. buildHeap: สร้าง Max-Heap ใน array เดิมใน O(N)
  2. deleteMax ซ้ำๆ: swap root (index 0 = ค่ามากสุด) กับตัวสุดท้ายของ heap (index j) → ลด logical heap size ลง 1 → percolate down root ใหม่

หลัง N−1 swap array จะเรียงจากน้อยไปมาก — ค่ามากสุดที่ root ไปอยู่ท้าย array ถูกตำแหน่งพอดี (ถ้าใช้ Min-Heap จะได้ลำดับจากมากไปน้อย ยกเว้นใช้หน่วยความจำเพิ่ม)

template <typename Comparable>
void heapsort( vector<Comparable> & a ) {
    // Phase 1: buildHeap
    for( int i = a.size( ) / 2 - 1; i >= 0; --i )
        percDown( a, i, a.size( ) );

    // Phase 2: deleteMax swaps
    for( int j = a.size( ) - 1; j > 0; --j ) {
        std::swap( a[ 0 ], a[ j ] );
        percDown( a, 0, j );
    }
}

template <typename Comparable>
void percDown( vector<Comparable> & a, int i, int n ) {
    int child;
    Comparable tmp;
    for( tmp = std::move( a[ i ] ); 2 * i + 1 < n; i = child ) {
        child = 2 * i + 1;                              // left child
        if( child != n - 1 && a[ child ] < a[ child + 1 ] )
            ++child;                                    // เลือก child ที่ใหญ่กว่า
        if( tmp < a[ child ] )
            a[ i ] = std::move( a[ child ] );
        else
            break;
    }
    a[ i ] = std::move( tmp );
}

7. Lower Bound ของ Comparison Sort

Theorem comparison-based sorting ใดๆ ต้องใช้อย่างน้อย ⌈log₂(N!)⌉ การเปรียบเทียบในกรณีเลวร้ายที่สุด

พิสูจน์ด้วย Decision Tree

  • Decision tree คือ binary tree ที่แทนการเปรียบเทียบของ algorithm บนอินพุต N ตัว
  • แต่ละ internal node = การเปรียบเทียบ aᵢ < aⱼ
  • แต่ละ leaf = permutation ที่เรียงแล้วหนึ่งแบบ
  • มี permutation ทั้งหมด N! แบบ → ต้องมี leaf ≥ N! ใบ
  • binary tree ที่สูง h มี leaf ได้มากสุด 2h ⟹ 2h ≥ N! ⟹ h ≥ log₂(N!)

Stirling's Approximation

N! ≈ √(2πN) · (N/e)N ⟹ log₂(N!) ≈ N log₂N − N log₂e + ½ log₂(2πN) ≥ N log₂N − 1.44N = Ω(N log N)

Corollary comparison-based sort ใดๆ มี worst-case lower bound Ω(N log N) · ถ้าอยากได้ linear time (O(N)) ต้องใช้ algorithm ที่ ไม่อาศัยการเปรียบเทียบอย่างเดียว

8. Sorting แบบ Linear Time

8.1 Bucket Sort

  • สมมติอินพุตเป็นจำนวนเต็มในช่วง [0, M−1]
  • เตรียม array ของ list ว่าง M ช่อง (bucket) · สแกนอินพุต ใส่ x ลง bucket x · ต่อทุก bucket ตามลำดับ
  • Distribution O(N) + Concatenation O(M) = O(N + M) · ถ้า M = O(N) จะเป็น O(N)

8.2 Counting Sort

แบบ bucket sort ที่ใช้ array ของจำนวนนับ และทำให้ stable ได้ด้วยผลรวมสะสม:

  1. นับจำนวนครั้งของแต่ละ key ลง count ขนาด M
  2. แปลงเป็น prefix sum: count[i] += count[i-1]
  3. สแกนอินพุต จากหลังมาหน้า: สำหรับ x ตำแหน่งในผลลัพธ์คือ count[x] − 1 → เขียน x ลง output → count[x]--

สแกนจากหลัง: 1 → count[1] = 1 → B[0] · 3b → count[3] = 5 → B[4] · 3a → count[3] = 4 → B[3] · 8 → B[6] · 2b → B[2] · 2a → B[1] · 4 → B[5] ⟹ [1, 2a, 2b, 3a, 3b, 4, 8] (ตัวที่เท่ากันคงลำดับเดิม = stable)

8.3 Radix Sort

  • เรียงจำนวนเต็ม (หรือ string) ทีละหลัก โดยต้องเริ่มจาก หลักน้อยสุด (LSD) ไปหลักมากสุด (MSD) ด้วย stable sort (เช่น counting sort หรือ stable bucket sort)
  • ถ้าเริ่มจากหลักมากสุดก่อน pass ถัดไปของหลักต่ำกว่าจะ ทำลายลำดับที่เรียงไว้ของหลักสูง
  • คีย์มี P หลัก (pass) และ radix ขนาด B (bucket): O(P(N + B)) · ถ้า P, B คงที่ → O(N)

/* Radix sort an array of Strings of the same length */
void radixSortA( vector<string> & arr, int stringLen ) {
    const int BUCKETS = 256;
    vector<vector<string>> buckets( BUCKETS );

    // เรียงจาก LSD ไป MSD
    for( int pos = stringLen - 1; pos >= 0; --pos ) {
        for( string & s : arr )
            buckets[ s[ pos ] ].push_back( std::move( s ) );

        int idx = 0;
        for( auto & thisBucket : buckets ) {
            for( string & s : thisBucket )
                arr[ idx++ ] = std::move( s );
            thisBucket.clear( );
        }
    }
}

9. Simulation: ลองเล่น Sorting

เลือก algorithm แล้วแก้อินพุตได้เอง (สูงสุด 15 ตัว) กด เริ่ม เพื่อดูทีละขั้น (เล่นอัตโนมัติ หรือกดย้อน/ถัดไป) · ถ้ามีค่าซ้ำ ตัวตนจะถูกติดป้าย a, b, … ตามลำดับในอินพุต เพื่อดูเรื่อง stability ว่าตัวที่เท่ากันสลับที่กันหรือไม่ · ตัวนับด้านล่างแสดงจำนวนการเปรียบเทียบและ swap/เลื่อน

กำลังเทียบ / ช่วงซ้าย swap / ย้าย / ช่วงขวา อยู่ถูกตำแหน่งแล้ว pivot
ลองดู
  • Selection Sort: ใส่ 2, 2, 1 → 2a กับ 2b สลับที่ (unstable)
  • Insertion Sort: ใส่ 1, 2, 3, 4, 5 → เทียบแค่ 4 ครั้ง ไม่ shift เลย (O(N)) · ลอง 5, 4, 3, 2, 1 เทียบ
  • Quicksort: ลองใส่ข้อมูลที่เรียงแล้ว 1, 2, 3, 4, 5, 6, 7, 8 → median-of-three ทำให้ partition สมดุล
  • Counting / Radix: ค่าซ้ำยังคงลำดับเดิม (stable)

แบบฝึกหัด

1) Selection Sort กับ array 6 ตัว ต้องเปรียบเทียบกี่ครั้ง และ swap มากสุดกี่ครั้ง? เทียบ N(N−1)/2 = 6·5/2 = 15 ครั้ง เสมอ (ไม่ขึ้นกับอินพุต) · swap ไม่เกิน N−1 = 5 ครั้ง
2) [3, 2, 1] มีกี่ inversion? Insertion Sort ต้อง shift กี่ครั้ง? และ N = 5 เฉลี่ยมี inversion เท่าไร? inversion: (3,2), (3,1), (2,1) = 3 คู่ · shift ทุกครั้งลบได้ 1 inversion จึง shift 3 ครั้ง · เฉลี่ย N = 5: N(N−1)/4 = 5·4/4 = 5 คู่
3) ทำไม Merge Sort stable แต่ Selection Sort ไม่ stable? Merge เลือกจากครึ่งซ้ายก่อนเมื่อค่าเท่ากัน (a[leftPos] <= a[rightPos]) จึงรักษาลำดับ · Selection swap ตัวน้อยสุดกลับมาที่หัว suffix ซึ่งอาจข้ามตัวที่ค่าเท่ากันไปได้ เช่น [2a, 2b, 1] → [1, 2b, 2a]
4) Quicksort เลือก pivot เป็นตัวแรก แล้วอินพุตเรียงอยู่แล้ว เวลาเป็นเท่าไร? แก้อย่างไร? pivot เป็นค่าต่ำสุดทุกครั้ง → T(N) = T(N−1) + O(N) = Θ(N²) · แก้ด้วย median-of-three (หรือสุ่ม pivot) → อินพุตที่เรียงแล้วแบ่งสมดุล
5) ทำ Counting Sort ให้ [3a, 1, 3b] (key 1..3) count = [1, 0, 2] → prefix = [1, 1, 3] · สแกนจากหลัง: 3b → count[3] = 3 → B[2] (count[3] = 2) · 1 → count[1] = 1 → B[0] · 3a → count[3] = 2 → B[1] · ผล: [1, 3a, 3b] (stable)
6) ทำไม Radix Sort ต้องเริ่มจากหลักน้อยสุด และต้องใช้ stable sort ในแต่ละ pass? เพราะแต่ละ pass ใหม่จะเรียงตามหลักที่สูงกว่า โดยตัวที่หลักนั้นเท่ากันต้องคงลำดับจาก pass ก่อน (ซึ่งเรียงตามหลักต่ำกว่าไว้แล้ว) → ต้อง stable · ถ้าเริ่มจาก MSD pass ของหลักต่ำจะทำลายลำดับของหลักสูงที่เรียงไว้
7) ทำไมไม่มี comparison sort ที่เร็วกว่า N log N ในกรณีเลวร้ายที่สุด แต่ Counting Sort ทำได้ O(N + M)? Decision tree ต้องมี leaf ≥ N! ใบ จึงสูงอย่างน้อย log₂(N!) = Ω(N log N) สำหรับ comparison sort · Counting Sort ไม่ได้ตัดสินใจจากการเทียบ key แต่ใช้ค่า key เป็น index ตรงๆ จึงอยู่นอกโมเดลนี้ (แต่ต้องรู้ช่วงของ key)
