1. แนวคิด Hashing

1.1 ปัญหาการค้นหา (ทบทวน)

  • Array / List: ค้นหา O(N) (ไม่เรียง) หรือ O(log N) (เรียงแล้วใช้ binary search)
  • Binary Search Tree: เฉลี่ย O(log N) แต่ถ้าไม่สมดุลแย่สุดเป็น O(N)
  • Balanced Search Tree (AVL, B-Tree): การันตี O(log N) ทั้ง search / insert / delete
เป้าหมายของ Hashing ทำ search, insert, delete ได้ใน เวลาคงที่เฉลี่ย O(1) ได้ไหม?

1.2 Direct Address Table (DAT)

ถ้า key เป็นจำนวนเต็มไม่ซ้ำในช่วงเล็กๆ [0, U−1] ก็ใช้ key เป็น index ของ array ได้ตรงๆ: เก็บด้วย T[k] = element และค้นหาด้วยการอ่าน T[k] ใน O(1)

ข้อเสีย ถ้า universe ของ key U ใหญ่มาก (เช่น รหัสนักศึกษา 9 หลัก → U = 10⁹) แต่เก็บจริงแค่ N = 100 ตัว จะเปลืองหน่วยความจำมหาศาล

1.3 Hash Table

แก้ปัญหาโดยแมป key จาก universe U ขนาดใหญ่ ไปยังตาราง T ขนาด M ที่เล็กกว่ามาก (M ≪ U) ด้วย Hash Function h

  • Hash Function h: ฟังก์ชันที่แมป key k ไปเป็น index i = h(k) ในช่วง [0, M−1]
  • Hash Value: จำนวนเต็ม h(k) คือช่อง (slot) ที่ key นั้นถูกเก็บ
  • Hash Table: array ขนาด M ที่เก็บข้อมูล

1.4 Collision

เพราะ M ≪ U ตาม Pigeonhole Principle ย่อมมี key บางตัวลงช่องเดียวกันแน่นอน

นิยาม Collision เกิดเมื่อ key สองตัวที่ต่างกัน k₁ ≠ k₂ มี hash value เท่ากัน: h(k₁) = h(k₂)
ตัวอย่าง h(k) = k mod 10: h(15) = 5 และ h(25) = 5 → ชนกันที่ช่อง 5 ต้องมีวิธีแก้ (collision resolution)

2. Hash Function

2.1 เป้าหมายในการออกแบบ

  1. คำนวณง่ายและเร็ว — ใช้เวลา O(1) เทียบกับขนาดตาราง
  2. กระจายสม่ำเสมอ (Uniform Distribution) — กระจาย key ให้ทั่วทุกช่องเพื่อลด collision
ทำไม TableSize ควรเป็นจำนวนเฉพาะ (prime)? ถ้า key ไม่สุ่มจริง (เช่น มีตัวประกอบร่วมกัน เป็นพหุคูณของ 10) การเลือกขนาดตารางเป็น prime ช่วยให้ key กระจายทั่วตารางภายใต้ modulo และป้องกัน clustering

2.2 Hash Function สำหรับจำนวนเต็ม

วิธีมาตรฐานคือ h(k) = k mod TableSize

✘ ตัวอย่างไม่ดี: TableSize = 10

ถ้า key ทั้งหมดลงท้ายด้วย 0 เช่น 10, 20, 110, 250 → h = 0, 0, 0, 0
ทุกตัวลงช่อง 0 → collision 100% และ search กลายเป็น O(N)

✔ ตัวอย่างดี: TableSize = 11 (prime)

10 mod 11 = 10 · 20 mod 11 = 9 · 110 mod 11 = 0 · 250 mod 11 = 8
กระจายออกไปคนละช่อง

2.3 Hash Function สำหรับ String

Method 1: ผลรวมรหัส ASCII

C++ · Simple ASCII Sum
int hash( const string & key, int tableSize )
{
    int hashVal = 0;
    for( char ch : key )
        hashVal += ch;
    return hashVal % tableSize;
}

ข้อเสีย: กระจายไม่ดี เช่น TableSize = 10,007 และ key ยาวไม่เกิน 8 ตัวอักษร (ASCII ≤ 127) ผลรวมมากสุดคือ 127 × 8 = 1,016 → ช่อง [1017, 10006] ไม่ถูกใช้เลย!

Method 2: ถ่วงน้ำหนัก 3 ตัวแรก

C++ · Weighted First 3 Chars
int hash( const string & key, int tableSize )
{
    return ( key[ 0 ] + 27 * key[ 1 ] +
             729 * key[ 2 ] ) % tableSize;
}
  • สมมติ key ยาว ≥ 3 ตัวอักษร · 27 = ตัวอักษร 26 ตัว + ช่องว่าง, 729 = 27²
  • ข้อเสีย: ภาษาอังกฤษไม่สุ่ม — จาก 17,576 combination ของ 3 ตัวอักษร มีที่ปรากฏจริงเพียง 2,851 แบบ → ใช้ตารางแค่ ~28% แม้ในกรณีดีที่สุด

Method 3: Polynomial Rolling Hash (Horner's Rule)

C++ · Horner's Rule
unsigned int hash( const string & key, int tableSize )
{
    unsigned int hashVal = 0;
    for( char ch : key )
        hashVal = 37 * hashVal + ch;
    return hashVal % tableSize;
}
  • คำนวณ H = Σ key[L−1−i] · 37i โดยใช้ตัวอักษร ทุกตัว
  • ใช้ Horner's rule คำนวณ polynomial อย่างมีประสิทธิภาพ: ((k₂ · 37 + k₁) · 37) + k₀
  • ใช้ unsigned int จึงไม่เกิดปัญหา overflow แบบ undefined (ค่าจะ wrap-around)

2.4 Trace: Horner's Rule กับ "cat"

ASCII: 'c' = 99, 'a' = 97, 't' = 116 · multiplier = 37

Step 1: เริ่มต้น

hashVal = 0

Step 2: 'c'

hashVal = 37 × 0 + 99 = 99

Step 3: 'a'

hashVal = 37 × 99 + 97 = 3663 + 97 = 3760

Step 4: 't'

hashVal = 37 × 3760 + 116 = 139120 + 116 = 139236
Index = 139236 mod TableSize

4. Separate Chaining

วิธีแก้ collision แบบแรก: ให้แต่ละช่องของตารางเก็บ linked list ของทุกตัวที่ hash ไปช่องนั้น

  • Search: hash หาช่อง แล้วเดินไล่ list
  • Insert: เช็กใน list ว่าซ้ำไหม ถ้าไม่ซ้ำ ใส่ที่ หัว (front) ของ list (สะดวก และได้ temporal locality)
  • Delete: หา node ใน list แล้วลบทิ้ง
Load Factor λ λ = N / TableSize สำหรับ separate chaining ค่าที่ดีคือ λ ≈ 1 · ความยาว list เฉลี่ย = λ

4.1 โค้ด C++

C++ · Separate Chaining: class interface
template <typename HashedObj>
class HashTable {
public:
    explicit HashTable( int size = 101 ) : theLists( nextPrime( size ) ), currentSize{ 0 } {}
    bool contains( const HashedObj & x ) const;
    void makeEmpty();
    bool insert( const HashedObj & x );
    bool remove( const HashedObj & x );
private:
    vector<list<HashedObj>> theLists;   // array of linked lists
    int currentSize;
    void rehash();
    size_t myhash( const HashedObj & x ) const {
        static hash<HashedObj> hf;
        return hf( x ) % theLists.size();
    }
};
C++ · Separate Chaining: contains / insert / remove
template <typename HashedObj>
bool HashTable<HashedObj>::contains( const HashedObj & x ) const {
    auto & whichList = theLists[ myhash( x ) ];
    return find( begin( whichList ), end( whichList ), x ) != end( whichList );
}

template <typename HashedObj>
bool HashTable<HashedObj>::insert( const HashedObj & x ) {
    auto & whichList = theLists[ myhash( x ) ];
    if ( find( begin( whichList ), end( whichList ), x ) != end( whichList ) )
        return false;                        // Duplicate
    whichList.push_back( x );
    if ( ++currentSize > theLists.size() )
        rehash();                            // Load factor > 1
    return true;
}

template <typename HashedObj>
bool HashTable<HashedObj>::remove( const HashedObj & x ) {
    auto & whichList = theLists[ myhash( x ) ];
    auto itr = find( begin( whichList ), end( whichList ), x );
    if ( itr == end( whichList ) ) return false;   // Not found
    whichList.erase( itr );
    --currentSize;
    return true;
}
หมายเหตุ โค้ดข้างบนใช้ push_back (ใส่ท้าย list) แต่ใน trace ของสไลด์ใส่ที่ หัว list — ต่างกันแค่ลำดับใน list ไม่กระทบความถูกต้อง · Simulator ในหน้านี้ใช้ตามสไลด์ (ใส่หัว list)

4.2 Trace: insert ค่ากำลังสอง 0, 1, 4, 9, 16, 25, 36, 49, 64, 81 (h(x) = x mod 10)

4.3 Trace: Search / Remove จากตารางข้างบน

  1. Search 36 (สำเร็จ): h(36) = 6 → list ช่อง 6 คือ [36 → 16] → node แรกคือ 36 → พบ (เทียบ 1 ครั้ง)
  2. Search 56 (ไม่สำเร็จ): h(56) = 6 → เทียบกับ 36 ไม่ตรง → เทียบกับ 16 ไม่ตรง → ถึงท้าย list → ไม่พบ (เทียบ 2 ครั้ง)
  3. Remove 16: h(16) = 6 → node แรก 36 ไม่ตรง → node สอง 16 ตรง → ลบและต่อ link → ช่อง 6 เหลือ [36]

5. Open Addressing: Linear Probing

ใน Open Addressing ข้อมูลทุกตัวเก็บ ในตัว array เอง — ไม่มี linked list เมื่อชนจะลองช่องอื่นไปเรื่อยๆ จนเจอช่องว่าง:

Probing Sequence hi(x) = ( h(x) + f(i) ) mod TableSize  โดย f(i) คือ collision resolution function และ f(0) = 0

ข้อจำกัดของ Open Addressing

  • ต้องใช้ตารางใหญ่กว่า separate chaining
  • ต้องคุม load factor ให้ λ < 0.5
  • Deletion: ลบจริงๆ ไม่ได้ เพราะจะตัด search path ของ key อื่น ต้องใช้ Lazy Deletion — ทำเครื่องหมายช่องเป็น DELETED แทน

5.1 Linear Probing: f(i) = i

ตรวจช่องถัดไปตามลำดับ (วนกลับต้นตารางเมื่อถึงท้าย)

Primary Clustering ช่องที่ถูกใช้จะรวมเป็นก้อนติดกัน (cluster) — key ใดที่ hash เข้า cluster ต้อง probe ผ่านทั้งก้อน และทำให้ก้อนยิ่งใหญ่ขึ้น · จำนวน probe เฉลี่ยของ insert / unsuccessful search ≈ ½ (1 + 1/(1−λ)²) พุ่งเร็วมากเมื่อ λ → 1

5.2 Trace: insert 89, 18, 49, 58, 69 (M = 10, h(k) = k mod 10)

6. Open Addressing: Quadratic Probing

f(i) = i² — ตรวจช่องที่ห่างไป +1, +4, +9, +16, … จากตำแหน่ง hash เริ่มต้น

  • ขจัด primary clustering
  • Secondary Clustering: key ที่ hash ได้ตำแหน่งเดียวกันยัง probe ตามลำดับเดียวกัน (เสียเพิ่มน้อยกว่า 0.5 probe)
  • Probing Limit: ถ้าตารางเต็มเกิน 50% ไม่การันตีว่าจะหาช่องว่างเจอ

6.1 Trace: insert 89, 18, 49, 58, 69 (M = 10)

6.2 Theorem 5.1: การันตีของ Quadratic Probing

Theorem ถ้าใช้ quadratic probing และ TableSize M เป็น prime แล้ว key ใหม่ ใส่ได้เสมอ ตราบที่ตารางว่างอย่างน้อยครึ่งหนึ่ง
พิสูจน์ (ย่อ) ให้ M เป็น prime คี่ > 3 · ตำแหน่ง probe แรก ⌈M/2⌉ ตัว คือ h(x) + i² mod M และ h(x) + j² mod M โดย 0 ≤ i, j ≤ ⌊M/2⌋
สมมติว่าสองตำแหน่งซ้ำกัน ทั้งที่ i ≠ j → i² ≡ j² (mod M) → (i − j)(i + j) ≡ 0 (mod M)
เพราะ M เป็น prime ต้องมี (i − j) ≡ 0 หรือ (i + j) ≡ 0 (mod M) อย่างใดอย่างหนึ่ง แต่
  • (i − j) ≡ 0 เป็นไปไม่ได้ เพราะ i ≠ j และ 0 ≤ i, j ≤ ⌊M/2⌋
  • (i + j) ≡ 0 เป็นไปไม่ได้ เพราะ i + j > 0 และ i + j ≤ 2⌊M/2⌋ < M
ดังนั้นตำแหน่งแรก ⌈M/2⌉ ตัวต่างกันหมด → ถ้าตารางว่าง≥ ครึ่งหนึ่ง ย่อมเจอช่องว่างแน่นอน ∎

6.3 โค้ด C++ ของ Probing Hash Table

C++ · Probing HashTable: class
template <typename HashedObj>
class HashTable {
public:
    explicit HashTable( int size = 101 ) : array( nextPrime( size ) ) { makeEmpty(); }
    bool contains( const HashedObj & x ) const { return isActive( findPos( x ) ); }
    bool insert( const HashedObj & x );
    bool remove( const HashedObj & x );
    enum EntryType { ACTIVE, EMPTY, DELETED };
private:
    struct HashEntry {
        HashedObj element;
        EntryType info;
        HashEntry( const HashedObj & e = HashedObj{ }, EntryType i = EMPTY )
          : element{ e }, info{ i } {}
    };
    vector<HashEntry> array;
    int currentSize;
    bool isActive( int currentPos ) const { return array[ currentPos ].info == ACTIVE; }
    int findPos( const HashedObj & x ) const;
    void rehash();
};
C++ · findPos และ insert (quadratic probing)
template <typename HashedObj>
int HashTable<HashedObj>::findPos( const HashedObj & x ) const {
    int offset = 1;
    int currentPos = myhash( x );
    while ( array[ currentPos ].info != EMPTY && array[ currentPos ].element != x ) {
        currentPos += offset;        // F(i) = F(i-1) + 2i - 1
        offset += 2;
        if ( currentPos >= array.size() )
            currentPos -= array.size();
    }
    return currentPos;
}

template <typename HashedObj>
bool HashTable<HashedObj>::insert( const HashedObj & x ) {
    int currentPos = findPos( x );
    if ( isActive( currentPos ) ) return false;   // Duplicate
    array[ currentPos ].element = x;
    array[ currentPos ].info = ACTIVE;
    if ( ++currentSize > array.size() / 2 )
        rehash();                                 // Load factor > 0.5
    return true;
}

สังเกต: findPos หยุดเมื่อเจอ ช่องว่าง หรือช่องที่มี key เดียวกัน (ไม่ว่า ACTIVE หรือ DELETED) · ใช้ความสัมพันธ์ F(i) = F(i−1) + 2i − 1 เพื่อเลี่ยงการคูณ · และ remove แค่เปลี่ยน info เป็น DELETED

7. Open Addressing: Double Hashing

f(i) = i · h₂(x) โดย h₂(x) คือ hash function ตัวที่สองที่ใช้คำนวณ step size ของการ probe

การออกแบบ h₂(x)

  • h₂(x) ต้อง ไม่เป็น 0 เด็ดขาด
  • TableSize M ต้องเป็น prime เพื่อให้ probe ได้ครบทุกช่อง
  • ตัวเลือกที่นิยม: h₂(x) = R − (x mod R) โดย R เป็น prime ที่น้อยกว่า M

ในทางทฤษฎี double hashing เทียบเท่า random probing แต่ในทางปฏิบัติ quadratic probing ง่ายกว่าและไม่ต้องมี hash function ตัวที่สอง

7.1 Trace: insert 89, 18, 49, 58, 69 (M = 10, h₁(x) = x mod 10, h₂(x) = 7 − (x mod 7), R = 7)

8. Rehashing

เมื่อ load factor สูงเกินไป ประสิทธิภาพจะตก จึงต้อง rehash:

  1. Trigger เมื่อ λ เกินเกณฑ์ (เช่น λ > 0.5 สำหรับ probing, λ > 1.0 สำหรับ chaining)
  2. สร้างตารางใหม่ขนาด ประมาณ 2 เท่า (ต้องปัดเป็น prime ตัวถัดไป)
  3. Scan ตารางเก่า แล้ว re-insert ทุกตัวที่ active ลงตารางใหม่ด้วย hash function ใหม่ ตามขนาดใหม่
  4. ใช้เวลา O(N) แต่เกิดไม่บ่อย → ต้นทุนต่อการ insert แบบ amortized ยังเป็น O(1)

8.1 Trace

ตั้งต้น: insert 13, 15, 24, 6 ลง linear probing ขนาด 7 (h(x) = x mod 7): 13 → 6, 15 → 1, 24 → 3, 6 → ชนที่ 6 → probe (6+1) mod 7 = 0

Insert 23: h(23) = 23 mod 7 = 2 → ช่อง 2 ว่าง วางที่ 2 · ตอนนี้มี 5 ตัวใน 7 ช่อง → λ = 5/7 ≈ 71.4% > 50% → Rehash! ขนาดใหม่ = 7 × 2 = 14 → prime ตัวถัดไปคือ 17 · hash function ใหม่ h′(x) = x mod 17

Scan ตารางเก่าตามลำดับ index: 6, 15, 23, 24, 13 แล้ว insert ลงตารางขนาด 17:

หมายเหตุ ตามกฎ λ > 0.5 จริงๆ ตาราง 7 ช่องที่มี 4 ตัว (λ = 4/7 ≈ 57%) ก็ควร rehash แล้ว · สไลด์ตั้งต้นแบบนี้เพื่อให้เห็นขั้นตอนชัด ถ้าอยากทำซ้ำใน Simulation ให้ปิด "auto rehash" แล้วกดปุ่ม Rehash เอง

9. Simulation: ลองเล่น Hash Table

เลือกวิธีจัดการ collision และ TableSize แล้ว Insert / Search / Remove เพื่อดูทีละขั้น (เล่นอัตโนมัติ หรือกดย้อน/ถัดไปเอง) · ลองใส่ 89, 18, 49, 58, 69 ใน 4 โหมดแล้วเทียบกับ trace ข้างบน · ลอง Remove แล้ว Search เพื่อดู lazy deletion · ลองเปลี่ยนเป็น TableSize ที่ไม่ใช่ prime กับ Quadratic แล้วใส่ key หลายตัวที่ชนกัน

แบบฝึกหัด

1) Linear probing, M = 7, h(x) = x mod 7: insert 18, 25, 11, 4 ผลเป็นอย่างไร? 18 → 4 · 25 → h = 4 ชน → 5 · 11 → h = 4 ชน 4, 5 → 6 · 4 → h = 4 ชน 4, 5, 6 → วนไป 0
ผลลัพธ์: index 0 = 4, index 4 = 18, index 5 = 25, index 6 = 11 (ช่อง 1–3 ว่าง)
2) Quadratic probing, M = 11: insert 22, 33, 44 (ทั้งหมด h = 0) ลงช่องไหน? 22 → 0 · 33: ชนที่ 0 → (0 + 1²) = 1 ว่าง → ช่อง 1 · 44: ชน 0 → ชน 1 → (0 + 2²) = 4 → ช่อง 4
3) Double hashing, M = 11, R = 7, h₂(x) = 7 − (x mod 7): insert 12 แล้ว 23 12 → h = 1 วางช่อง 1 · 23 → h = 1 ชน · h₂(23) = 7 − (23 mod 7) = 7 − 2 = 5 → (1 + 5) mod 11 = 6 ว่าง → วางช่อง 6
4) ทำไม open addressing ถึงลบ key โดยทำให้ช่องกลับเป็น EMPTY ตรงๆ ไม่ได้? ตัวอย่าง linear probing M = 10: insert 89 (ช่อง 9) แล้ว 49 (ชนที่ 9 → ช่อง 0) · ถ้าลบ 89 แล้วทำให้ช่อง 9 เป็น EMPTY จริง การ search 49 จะเริ่มที่ช่อง 9 เจอ EMPTY ก็หยุด → สรุปผิดว่า "ไม่พบ" · จึงใช้ lazy deletion (DELETED) ให้ probe เดินผ่านต่อได้ (ลองใน Simulation: Remove 89 แล้ว Search 49)
5) Quadratic probing ต้องการให้ M เป็น prime และตารางว่างอย่างน้อยครึ่งหนึ่งเพราะอะไร? Theorem 5.1: เมื่อ M เป็น prime ตำแหน่ง probe แรก ⌈M/2⌉ ตัว (h(x) + i² mod M) จะต่างกันทั้งหมด จึงการันตีว่าถ้าตารางว่าง ≥ ครึ่งหนึ่งต้องเจอช่องว่าง · ถ้า M ไม่เป็น prime หรือ λ > 0.5 อาจ probe วนซ้ำช่องเดิมและใส่ไม่ได้ ทั้งที่ยังมีช่องว่าง
