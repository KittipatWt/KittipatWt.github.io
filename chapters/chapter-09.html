1. Set ADT

Set คือกลุ่มของ object ที่ ไม่ซ้ำกัน และไม่มีแนวคิดเรื่อง key หรือ order ที่ชัดเจน

1.1 คุณสมบัติของ std::set

  • Uniqueness: ทุก element ไม่ซ้ำ — การ insert ซ้ำจะถูกเพิกเฉย
  • Sorted: เก็บเรียงลำดับ (น้อย→มาก เป็นค่าเริ่มต้น)
  • Immutable: แก้ค่า element ตรงๆ ไม่ได้ ต้อง erase แล้ว insert ใหม่
  • Under the hood: มักสร้างจาก balanced binary search tree (Red-Black Tree)

ตัวอย่างการใช้: เซตของ record ในฐานข้อมูล (intersection สำหรับ query แบบ AND), เซตของ URL ที่ตรงกับ keyword ใน search engine, อีเมล, เพื่อนใน Facebook, รายการสินค้าในคลัง

1.2 ฟังก์ชันพื้นฐาน

Core ADT

insert(e) — เพิ่ม e คืน iterator (ไม่สำเร็จถ้าซ้ำ)
find(e) — คืน iterator ของ e หรือ end() ถ้าไม่พบ
erase(e) — ลบ e
begin() / end() — iterator สำหรับไล่ element

STL Extensions

lower_bound(e) — iterator ตัวแรกที่ ≥ e
upper_bound(e) — iterator ตัวแรกที่ > e
equal_range(e) — คู่ iterator ของช่วง element ที่เท่ากับ e

1.3 รายละเอียด insert, erase, find

insert มี 2 แบบ

  1. pair<iterator, bool> insert(const Object & x); — คืน pair: iterator ชี้ element (ที่ใส่ใหม่หรือที่มีอยู่แล้ว) และ bool บอกว่า insert สำเร็จไหม
  2. iterator insert(iterator hint, const Object & x); — ระบุ hint ว่า x ควรอยู่ตรงไหน ถ้า hint ถูกต้อง insert ใช้ O(1) ถ้าไม่ถูกจะถอยกลับไปเป็น O(log N)
C++ · Hint insertion
set<int> s;
for (int i = 0; i < 100000; ++i) {
    s.insert(s.end(), i);   // O(1) เพราะ s.end() คือตำแหน่งที่ถูกต้องเสมอ
}

erase มี 3 แบบ

  1. By value: int erase(const Object & x) — ลบ x ถ้ามี คืนจำนวนที่ลบ (0 หรือ 1)
  2. By iterator: iterator erase(iterator itr) — ลบตัวที่ itr ชี้ คืน iterator ของตัวถัดไป · itr เดิมใช้ไม่ได้แล้ว (stale)!
  3. Range: iterator erase(iterator start, iterator end) — ลบทุกตัวในช่วง [start, end)

find

iterator find(const Object & x) const; คืน iterator ถ้าเจอ หรือ end() ถ้าไม่เจอ — ให้ข้อมูลมากกว่า bool เพราะเข้าถึงตัวที่เจอได้ทันทีโดยไม่ต้องค้นซ้ำ

1.4 Custom Ordering

ค่าเริ่มต้นใช้ std::less<Object> (เรียกตัวดำเนินการ <) เปลี่ยนได้โดยส่ง function object เข้าไป:

C++ · Case-insensitive set
struct CaseInsensitiveCompare {
    bool operator()(const string& lhs, const string& rhs) const {
        return strcasecmp(lhs.c_str(), rhs.c_str()) < 0;
    }
};

int main() {
    set<string, CaseInsensitiveCompare> s;
    s.insert("Hello");
    s.insert("HeLLo");   // ซ้ำแบบไม่สนตัวพิมพ์ → ถูกเพิกเฉย
    cout << "Size: " << s.size() << endl;   // พิมพ์ 1
}

1.5 การสร้างและไล่ดู Set

C++ · Initializing and Traversing
#include <iostream>
#include <set>
using namespace std;

int main() {
    set<int> s1;                              // Default: Ascending Order
    set<int, greater<int>> s2;                // Descending Order
    set<int, greater<int>> s3 = {6, 10, 5, 1};   // s3 = {10, 6, 5, 1}
    set<int, greater<int>> s4(s3);            // Copy constructor

    int arr[] = {10, 4, 5, 61};
    set<int> s5(arr, arr + 4);                // s5 = {4, 5, 10, 61}

    // Traversal using iterators
    for (set<int>::iterator it = s5.begin(); it != s5.end(); ++it) {
        cout << *it << " ";
    }
    cout << endl;
}

2.2 โค้ด Union, Intersection, Difference

C++ · getUnion / getIntersection / getDifference
template <typename T>
set<T> getUnion(set<T> a, set<T> b) {
    set<T> result = a;
    for (typename set<T>::iterator it = b.begin(); it != b.end(); ++it) {
        result.insert(*it);          // ตัวซ้ำถูกเพิกเฉยเอง
    }
    return result;
}

template <typename T>
set<T> getIntersection(set<T> a, set<T> b) {
    set<T> result;
    for (typename set<T>::iterator it = a.begin(); it != a.end(); ++it) {
        if (b.find(*it) != b.end()) {
            result.insert(*it);
        }
    }
    return result;
}

template <typename T>
set<T> getDifference(set<T> a, set<T> b) {
    set<T> result = a;
    for (typename set<T>::iterator it = b.begin(); it != b.end(); ++it) {
        result.erase(*it);
    }
    return result;
}

ดู trace ทีละขั้นของ A = {6, 12, 20, 32}, B = {6, 12, 42} ได้ใน Simulation (Set Operations)

Union ของตัวอย่างนี้

result = {6, 12, 20, 32} → b = 6, 12 อยู่แล้ว (ข้าม) → b = 42 ไม่อยู่ → insert → {6, 12, 20, 32, 42}

Intersection ของตัวอย่างนี้

result = { } → a = 6 ∈ B ✔ → 12 ∈ B ✔ → 20 ∉ B → 32 ∉ B → {6, 12}

2.3 High-Level Collection Operations (สไตล์ Java)

แทนที่จะวน loop เอง สร้าง primitive ระดับสูงก่อน แล้วประกอบเป็น union / intersection ได้กระชับ:

C++ · addAll / containAll / removeAll / retainAll
template <typename T>
void addAll(set<T> b, set<T>& a) {
    a.insert(b.begin(), b.end());
}

template <typename T>
bool containAll(set<T> b, set<T> a) {
    for (auto it = b.begin(); it != b.end(); ++it)
        if (a.find(*it) == a.end()) return false;
    return true;
}

template <typename T>
void removeAll(set<T> b, set<T>& a) {
    for (auto it = b.begin(); it != b.end(); ++it) a.erase(*it);
}

template <typename T>
void retainAll(set<T> b, set<T>& a) {
    for (typename set<T>::iterator it = a.begin(); it != a.end(); ) {
        if (b.find(*it) == b.end()) {
            it = a.erase(it);        // erase คืน iterator ของตัวถัดไป
        } else {
            ++it;
        }
    }
}

template <typename T>
set<T> getUnionUsingHelpers(set<T> setA, set<T> setB) {
    set<T> result;
    addAll(setA, result);
    addAll(setB, result);
    return result;
}

template <typename T>
set<T> getIntersectionUsingHelpers(set<T> setA, set<T> setB) {
    set<T> result;
    addAll(setA, result);
    retainAll(setB, result);
    return result;
}
ข้อควรระวังใน retainAll หลัง a.erase(it) iterator เดิมใช้ไม่ได้ ต้องใช้ค่าที่ erase คืนมา และไม่ ++it ซ้ำในกรณีที่ erase

3. Map ADT

Map คือ collection ของ key-element item (คู่ key-value) ที่ค้นหาได้

  • แต่ละ item เป็นคู่ (k, v)
  • key ต้องไม่ซ้ำ — ห้ามมีหลาย item ที่ key เดียวกัน
  • ใช้สำหรับ association, lookup, search

ตัวอย่าง: สมุดที่อยู่ (ชื่อ → ที่อยู่/อีเมล), DNS Resolver (โดเมน → IP เช่น cs16.net → 128.148.34.101), ทะเบียนนักศึกษา (รหัส → record)

3.1 ฟังก์ชันพื้นฐาน (สำหรับ map M)

  • put(k, v) — ถ้าไม่มี key k ให้ insert (k, v) · ถ้ามีแล้ว เขียนทับ value ด้วย v · คืน iterator
  • erase(k) — ลบ entry ที่ key k (ถ้าไม่พบจะ throw error)
  • erase(p) — ลบ entry ที่ iterator p ชี้
  • find(k) — คืน iterator ของ key k หรือ end() ถ้าไม่พบ
  • size() / empty() — จำนวน entry / ตรวจว่าว่างไหม
  • begin() / end() — iterator สำหรับไล่ดู

3.3 operator[] vs find

std::map overload ตัวดำเนินการ index: ValueType & operator[] (const KeyType & key);

  • key มีอยู่: คืน reference ของ value ที่ตรงกัน
  • key ไม่มี: insert key นั้นด้วย default value (เช่น 0.0 หรือ object ที่ default-construct) แล้วคืน reference ของ value ใหม่
"Accidental Insertion" side effect แค่ "อ่าน" ด้วย [] ก็ทำให้ map เปลี่ยนถาวรได้
C++ · operator[]
map<string, double> salaries;
salaries["Pat"] = 75000.00;       // insert "Pat" ด้วย 0.0 แล้ว assign เป็น 75000.00
cout << salaries["Jan"] << endl;  // พิมพ์ 0.0 แต่ "Jan" ถูก insert ถาวรด้วย!

เพราะ operator[] อาจแก้ map ได้ จึง เรียกกับ const map ไม่ได้ (เช่นในฟังก์ชันที่รับ const map<K,V>&) · ถ้าต้องการแค่ตรวจ/อ่านโดยไม่แก้ map ให้ใช้ find():

C++ · Safe lookup
map<string, double>::const_iterator itr = salaries.find("Chris");
if (itr == salaries.end()) {
    cout << "Not found!" << endl;       // ไม่ได้ insert "Chris"
} else {
    cout << "Salary: " << itr->second << endl;
}

salaries["Pat"] = 75000.0;

หา "Pat" → ไม่พบ → insert ("Pat", 0.0) → assign เป็น 75000.0
map: {"Pat" → 75000.0}

cout << salaries["Jan"];

หา "Jan" → ไม่พบ → insert ("Jan", 0.0) ถาวร → คืน reference 0.0
map: {"Pat" → 75000.0, "Jan" → 0.0}

salaries.find("Chris");

หา "Chris" → ไม่พบ → คืน end() · ไม่มี side-effect
map ยังเป็น {"Pat", "Jan"} เหมือนเดิม

3.4 Map แบบ Direct Address Table

Map ที่สร้างด้วย array ดิบ T[0..N−1]: key ต้องเป็นจำนวนเต็มในช่วง [0, N−1] และ item ที่ key k เก็บที่ T[k] ตรงๆ

  • insert, find, erase: O(1) · Space: O(N) (ขนาดช่วง key)
  • เปลืองที่: ถ้าจำนวน item n ≪ N ช่องส่วนใหญ่ถูกทิ้งว่าง เหมาะเมื่อ key หนาแน่น (n ใกล้ N)

3.5 STL Map: Insert และ Erase

C++ · Insertion / Deletion modes
#include <iostream>
#include <map>
using namespace std;

int main() {
    map<char, int> marks;
    // Insertion modes
    marks.insert(pair<char, int>('b', 30));            // 1. By std::pair
    marks.insert(map<char, int>::value_type('d', 50)); // 2. By value_type
    marks['e'] = 31;                                   // 3. By bracket operator

    // Deletion modes
    auto it = marks.find('b');
    if (it != marks.end()) {
        marks.erase(it);                               // 1. Erase by iterator
    }
    marks.erase('e');                                  // 2. Erase by key
    auto range_it = marks.find('d');
    if (range_it != marks.end()) {
        marks.erase(range_it, marks.end());            // 3. Erase range [iterator, end)
    }
}

ไล่ดูและลบจนหมด

C++ · Traversal & emptying loop
map<char, int> marks = {{'a', 10}, {'b', 20}, {'c', 30}};
cout << "Initial Size: " << marks.size() << "\n";
while (!marks.empty()) {
    // first = key, second = value ของตัวแรก
    cout << marks.begin()->first << " => " << marks.begin()->second << "\n";
    marks.erase(marks.begin());          // ลบตัวแรก
}
cout << "Final Size: " << marks.size() << "\n";

4. Dictionary ADT

Dictionary ก็คือ collection ของ key-element item ที่ค้นหาได้ เหมือน Map แต่

ต่างจาก Map ที่จุดเดียว Dictionary อนุญาตให้มี key ซ้ำ — หลาย item มี key เดียวกันได้
  • find(k) — คืน iterator ของ item หนึ่งตัวที่มี key k
  • findAll(k) — คืนช่วง iterator ของ ทุก item ที่มี key k
  • insert(k, v) — ใส่คู่ (k, v)
  • erase(k) — ลบ item หนึ่งตัว ที่มี key k

ตัวอย่าง: พจนานุกรมที่คำหนึ่งมีได้หลายความหมาย, log file ที่จัดกลุ่มตาม timestamp หรือ IP (ใน C++ คือ std::multimap)

5. Dictionary แบบ List

5.1 Unordered List (Log File)

แบบง่ายที่สุด: เก็บ element ต่อท้ายใน doubly-linked list หรือ circular array โดยไม่เรียงลำดับ

  • insert(k, v): O(1) (ต่อหัว/ท้าย)
  • find(k) / erase(k): O(N) (ต้องสแกนทั้งลำดับ)
  • Space: O(N)
  • เหมาะกับ: บันทึกประวัติที่เขียนถี่มากแต่ค้น/ลบน้อย เช่นประวัติการ login ของระบบ

Trace erase(2) บน log file { (5,A), (7,B), (2,C), (2,E) }: เทียบ key 5 → ไม่ตรง · เทียบ 7 → ไม่ตรง · เทียบ 2 → ตรง ลบ (2, C) · (ในสไลด์สแกนต่อ เจอ (2, E) ลบด้วย → ลบทุกตัวที่ key 2 เหลือ {(5,A), (7,B)}) · ลองได้ใน Simulation

หมายเหตุ นิยาม ADT ของสไลด์บอกว่า erase(k) ลบ หนึ่งตัว แต่ trace ของ log file ลบ ทุกตัว ที่ key ตรงกัน · ใน Simulation ผมทำตามนิยาม ADT (ลบตัวแรกที่เจอ) ถ้าต้องการลบทุกตัวให้กด erase ซ้ำ

5.2 Ordered Array / Sequence

เก็บใน array ที่เรียงตาม key:

  • find(k): O(log N) ด้วย Binary Search
  • insert(k, v): O(N) (ต้องเลื่อน element เพื่อแทรกให้เรียง)
  • erase(k): O(N) (ต้องเลื่อน element ปิดช่องว่าง)

ถ้าใช้ sorted linked list ล่ะ? Binary search เป็น O(log N) บน linked list ไม่ได้ เพราะเข้าถึงแบบ sequential (ต้องใช้ O(N) เพื่อไปถึงตรงกลาง) → find ถดถอยเป็น O(N)

6. Dictionary แบบ Tree

  • Binary Search Tree (BST): เฉลี่ย O(log N) ทั้ง find, insert, delete แต่แย่สุด O(N) ถ้า insert key ตามลำดับที่เรียงแล้ว (ต้นไม้เบี้ยวเป็นเส้นตรง เช่น 2 → 5 → 7)
  • Balanced Trees (AVL, Red-Black): การันตี worst-case O(log N) โดยใช้ rotation รักษาความสูง · ใช้ใน std::multimap

6.1 จัดการ Duplicate ใน Tree อย่างไร?

Approach A: เก็บ list ของ value ใน node

แต่ละ node เก็บ key ที่ไม่ซ้ำ + list ของ value (เช่น std::vector<Value>)
ต้นไม้เล็กกว่า และ rotation เหมือน map ทั่วไป
ตัวอย่าง: key=5 → {A} · key=2 → {C, E} · key=7 → {B}

Approach B: หลาย node ที่ key เดียวกัน

กำหนดกฎ BST ว่า left child ≤ parent · key ซ้ำถูก insert เป็น node แยกต่างหาก
ต้นไม้สูงขึ้น และเวลา traverse ต้องสแกน subtree ต่อ

6.2 Trace: insert 5, 2, 7, 2 (ซ้ำ) ด้วยกฎ left ≤ parent

Step 1: Insert 5

ต้นไม้ว่าง → 5 เป็น root

Step 2: Insert 2

เทียบ 5: 2 ≤ 5 → ไปซ้าย · ซ้ายว่าง → ใส่ 2

Step 3: Insert 7

เทียบ 5: 7 > 5 → ไปขวา · ขวาว่าง → ใส่ 7

Step 4: Insert 2 (ซ้ำ)

เทียบ root 5: 2 ≤ 5 → ซ้าย · เทียบ node 2: 2 ≤ 2 → ซ้ายอีก! · ลูกซ้ายของ 2 ว่าง → ใส่ 2 ตัวซ้ำที่นี่

7. Dictionary แบบ Hash

Hash Table ใช้ hash function h(K) แมป key ไปยัง slot (bucket) · เฉลี่ย O(1) ทั้ง insert, lookup, deletion · แย่สุด O(N) ถ้าทุกตัวลง bucket เดียว · เพราะ key space ใหญ่กว่า M มาก จึงต้องมี collision resolution (ดู บทที่ 8)

7.1 Separate Chaining

แต่ละ bucket ชี้ไป linked list ของ entry ที่ hash มาที่ slot นั้น

  • Duplicates: จัดการง่าย — ต่อคู่ key-value ที่ซ้ำเข้าไปใน chain เดียวกัน
  • Load factor λ = N/M: เกิน 1 ได้ · เวลา search เฉลี่ย O(1 + λ)

Trace: insert (12, C), (7, B), (12, E) ลงตาราง M = 5 ด้วย h(K) = K mod 5

Step 1: Insert (12, C)

h(12) = 12 mod 5 = 2 → ต่อ chain ช่อง 2

2→12, C

Step 2: Insert (7, B)

h(7) = 7 mod 5 = 2 → ต่อ chain ช่อง 2 → (12, C) → (7, B)

2→12, C→7, B

h(12) = 2 → ต่อท้าย chain: (12, C) → (7, B) → (12, E)

2→12, C→7, B→12, E

7.2 Open Addressing

ทุก item เก็บในตัว array · ถ้า h(K) เต็มจะ probe:

  • Linear Probing: i = (h(K) + j) mod M — ปัญหา Primary Clustering (ช่องที่เต็มติดกันรวมเป็นก้อนยาว)
  • Quadratic Probing: i = (h(K) + j²) mod M — ขจัด primary clustering แต่มี Secondary Clustering (key ที่ hash ได้ index เดียวกัน probe ตามลำดับเดียวกัน)
  • Double Hashing: i = (h₁(K) + j · h₂(K)) mod M — ขจัดได้ทั้ง primary และ secondary clustering เพราะ step size ขึ้นกับ key · h₂(K) ต้อง ไม่เป็น 0 · สูตรที่นิยม h₂(K) = R − (K mod R) โดย R เป็น prime ที่ < M

ตัวอย่าง: M = 11, h₁(K) = K mod 11, h₂(K) = 7 − (K mod 7), insert K = 14: h₁(14) = 3 (ช่อง 3 เต็ม) → h₂(14) = 7 − 0 = 7 → probe 1: (3 + 7) mod 11 = 10

7.3 Duplicate ใน Open Addressing

  1. Insertion: key ซ้ำถูกวางในช่องว่างถัดไปใน probe sequence
  2. Search (findAll(k)): หยุดตอนเจอตัวแรกไม่ได้! ต้อง probe ต่อไปจนเจอช่อง empty (ไม่เคยถูกใช้) · ช่องที่เป็น tombstone (DELETED) ไม่ทำให้หยุด
  3. Erase: ต้องค้นตลอดสายเพื่อลบ value ที่ต้องการ
Performance Degradation เพราะ duplicate บังคับให้ search สแกน probe path ไปจนสุดทาง เมื่อมี key ซ้ำมาก open addressing จะช้าลงมาก → ควรใช้ Separate Chaining หรือ node ที่เก็บ list ของ value แทน

8.2 Map vs Dictionary

เลือก Map (key ห้ามซ้ำ, put เขียนทับ, มี operator[]) หรือ Dictionary (key ซ้ำได้, insert ไม่เขียนทับ, มี findAll) แล้วลองใส่/ค้น/ลบ · ตัวจำลองเก็บเป็น list ตามลำดับที่ใส่ (แบบ log file) เพื่อให้เห็นการสแกนทีละตัว · ใน Map ลอง m[k] โดยเว้น value ว่างกับ key ที่ไม่มี เพื่อดู accidental insertion

กำลังเทียบ พบ / ใส่ / แก้ ถูกลบ
ลองเทียบ กด "โหลดตัวอย่าง" ใน Map แล้ว put(2, E) → value ของ key 2 ถูกเขียนทับ · เปลี่ยนเป็น Dictionary โหลดตัวอย่างแล้ว insert(2, E) → มี key 2 สองตัว ลอง findAll(2) (ลำดับตรงกับ trace 3.2 และ 4)

เลือกใช้อันไหน?
  • Log File — เขียนถี่ ค้นน้อย
  • Direct Address Table — key เป็นจำนวนเต็มช่วงเล็กๆ
  • Tree Map — ต้องการ range query หรือผลลัพธ์เรียงลำดับ · tree การันตี bound แบบ sub-linear คงที่ และเก็บ duplicate ไว้ติดกัน
